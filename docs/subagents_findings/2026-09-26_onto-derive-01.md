# ONTO-DERIVE-01 a SQL-source Space derives, verifies, stores and uses its own ontology (dms#277)

Keywords: ONTO-DERIVE-01, CONNECT-ASK-01, space ontology, from_manifest, verify, fk_intact, onto_snapshot, unverified_join, no_declared_measure, source=space, dms-277
Main idea: On SQL-source ingest the Space's ontology is derived from the source catalog (objects = keyed tables, links = declared FKs only, attributes with landed types), verified against bronze, stored as a snapshot of the versioned ontology, re-measured at ask time, sent to Cortex (objects, verified links, keys; no measures) and enforced on generated SQL (a join must be a verified link).

PREFLIGHT: PARTIAL (ONTO-STORE-01 and A2-06 findings cover the store and scoped refusals; nothing covered deriving or using a Space ontology).

## Expected vs actual (before)

- Expected: a SQL-source Space asks against its own verified ontology; a join over a broken declared FK abstains naming it.
- Actual: `verify_source_links` measured the links once, put them in the ingest receipt and dropped them. `OntologyStore` had no non-test caller. The Space ask path passed no ontology (`demo_ontology_allowed=False`, `ontology=None`), so generated SQL could join anything granted: a join over an orphaned FK (inner join drops 52 of 107 students) or on the wrong column pair (`s.school_id = d.district_id`, returns 1 instead of 3) answered L2 with a green badge.

## Repro

`tests/test_onto_derive_01.py`: Space ingests a PostgreSQL source via `POST /v1/studio/sources/sql` (districts, schools, enrollments; FK `enrollments_school_id_fkey` planted with orphans). Mutating `unverified_join_reason` to `None` or `load_space_ontology` to `None` turns 1 and 5 of the 9 tests red. Real Postgres source + `PostgresOntologyStore`: `tests/control_plane/test_onto_derive_01_pg.py`.

## Root-cause class

Measured-then-dropped evidence: a check whose result reaches only a receipt, never the path that answers. Same class as SQLSRC-08 (#156).

## Invariants

Assert the artifact the customer receives (envelope asserts rows, text, badge). Silent fallback is a lie (store unreadable is a named `ontology_store_unavailable` abstain, never a no-ontology answer). Prove a gate can fail (mutations above). Fix the root-cause class (the ask path re-measures the stored ontology instead of trusting the snapshot).

## Ceiling / not done

- Measures: never derived (NEEDS_FOUNDER). The typed-plan path abstains `no_declared_measure`; generated SQL that writes its own aggregate (`SUM(col)`) is not a named measure and is not refused by this ticket.
- The join rule applies only to Spaces with a derived ontology. A Space without one (CSV uploads, pre-existing BIRD Spaces until re-derived) keeps the previous behaviour.
- A changed schema creates a `proposed` version (ONTO-STORE-01 rule); the `active` one keeps answering until confirm/reject lands (next ticket).
- The join rule checks that equalities match a verified many-to-one link; it does not check aggregate fan-out of parent-side columns (GRAIN-GUARD territory).

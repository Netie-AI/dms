# ORACLE-FIX-02 cq_audit_overdue judged at the engine date (dms#308)

Keywords: ORACLE-FIX-02, cq_audit_overdue, CURRENT_DATE, engine_clock, as-of, INVALID, zero-row, dms-308
Main idea: The certified oracle reads `CURRENT_DATE`, so its expected rows depend on the day the judge runs. The row judge now binds `CURRENT_DATE` to the date the answer engine read on the answer's own submit (envelope `engine_clock`), never the harness clock. A round whose engine date changed between the before and after probes is INVALID, never WRONG. No oracle SQL changed.

## Expected vs actual

- Expected: a correct answer, evaluated at the date the engine answered, judges OK.
- Actual at `f73b7ab`: the judge ran the oracle at the harness date. An answer with SUP-01..03, correct for an engine date of 2026-11-15, judged WRONG on 2026-09-26. A round that crossed engine midnight judged WRONG.
- On the DMS seeded lake the oracle does not error: it returns SUP-01, SUP-03 on 2026-09-26 through `run_oracle_select`. The `_OWN_ORACLE_ERROR` exemption was never needed on the seed. The harness-lake error (Cortex-side lake) was not reproduced in this container.

## Repro

`tests/test_oracle_fix_02.py`. On `f73b7ab`, `judge_envelope_detailed` with `engine_clock` 2026-11-15 and the seed-derived rows for that date returns WRONG.

## Root-cause class

Oracle evaluated against a different clock than the answer. Same class as a pinned as-of the answer does not share.

## Invariant

Assert the artifact the customer receives (the envelope carries the engine date the judge uses). Silent fallback is a lie: a missing engine date is ORACLE_ERROR, not the harness clock.

## Swap (hard rule 6)

`dms_executor/engine_clock.py` probes through the same Cortex submit. Swap: a Cortex submit result that carries the engine date replaces the probes; the envelope field stays.

## Ceiling

Two extra submits per clock-reading answer. Only SQL that reads the clock is probed. Live Cortex acceptance of the probe SQL is not verified here.

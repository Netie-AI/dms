# JOIN-HOLE-01

Keywords: JOIN-HOLE-01, dms-527, rule 16, unverified_join, _JoinRule, _one_read, not_one_read, CTE self-join, fan-out, recursive CTE, UNNEST, sqlglot scope sources, ROLLUP, UNPIVOT, ebe65cc

Main idea: The join allowlist's one-table shortcut counted base tables, not relations. A CTE read twice is one base table and two relations. The shortcut is now one read of one base table; every FROM item counts.

Expected: a statement that multiplies one table's rows through a second row source abstains `unverified_join:`.
Actual on `ebe65cc`: served `L2_VALIDATED` on `POST /v1/chat/ask` in a Space with a verified ontology. CTE `FROM c a, c b` showed 428 for a true 107; `JOIN ... ON` showed 24 for 10; a scalar subquery over the same CTE 40 for 10; a constant `UNION` derived table 214 for 107. The recursive CTE shape abstained `ungranted` on generate and the loop but was served 321 through the contract ask's `sql_used`.

Repro: `tests/test_join_hole_01.py::test_one_table_read_twice_abstains` (36 cases, 3 doors). Put `if lone:` back in `_JoinRule.check` and 58 tests go red.

Root-cause class: a shortcut keyed on a proxy count. "At most one base table" stood in for "nothing to join". sqlglot scope sources list every visible CTE, so the count has to come from what each FROM names.

Invariants: assert the artifact the customer receives (the envelope showed it, the function tests did not); fix the root-cause class (count relations, not CTE names); a control that blocks legitimate work is a failure (16 one-table shapes now abstain and are pinned by name); prove a gate can fail (mutation run).

Adversary round (a different run): the first fix keyed the projection row generator on sqlglot's `exp.Unnest`. `main.unnest`, `unlist`, `generate_subscripts`, `regexp_split_to_table` and `[1,2].unnest()` parse as an unknown function and still served 214 for 107. Same class as the original defect: a proxy (the parser's name for the node) stood in for the property (row count kept). Now any function sqlglot cannot type refuses outside WHERE, HAVING and QUALIFY. Cost: `date_part`, `dayname`, `hash`, `mode`, `list_sum`, `now`, `today`, `age` in a projection, GROUP BY or ORDER BY abstain; 758 of DuckDB 2.0.0's 1014 scalar, aggregate and macro names are untyped in sqlglot 27.29.0. A generated corpus of 711 statements run on DuckDB: the rule allows 4 with a wrong total, all four in the open set below.

Not closed here: `GROUP BY ROLLUP` / `GROUPING SETS` summed by an outer query and `UNPIVOT` double a one-table total with no second relation (served 214 for 107 on all three doors). Reported on #527 for routing.

Checked with the fixtures' Cortex fake, DuckDB 2.0.0, sqlglot 27.29.0, Python 3.13.18. A real Cortex, a file Space (#522) and the Yes door (#524) were not exercised.

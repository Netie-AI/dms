# JOIN-HOLE-01

Keywords: JOIN-HOLE-01, unverified_join, CTE, self-join, sqlglot, _one_base_read, cte_over_join, dms#527

A CTE name is not an `exp.Table`. `_JoinRule.check` counted only those sources and returned when it saw one base table, so `WITH c AS (SELECT * FROM t) SELECT ... FROM c a JOIN c b` never reached the join checks. The parent served the fanned-out total (schools 24 against a true 10, enrollments 428 against a true 107).

The early return is one base table with no join. The count walks the sqlglot AST: FROM and JOIN items, in the main query, each CTE body and each subquery. A scalar subquery that reads the same CTE, a one-row constant (`CROSS JOIN (SELECT 1)`), and `WITH RECURSIVE` that never names itself stay on that early return and still answer. A CTE joined to itself, a second multi-row FROM item, a CTE that names itself, or `(SELECT SUM(x) FROM c) * COUNT(*)` does not. Those fall through to the same checks (`cte_over_join`, `derived_table_over_join`, `set_operation`, or the link rules). The double-count (schools total 24 against a true 10) still fails closed.

`UNION ALL SELECT 0` on one table is not a join. The extra 0 row can make the old total wrong, so the gate returns `unverified_join:rowset_reconfirm` and the ask shows that SQL on the reconfirm card. It does not serve the rows and it does not dead-end as a bare abstain. A set operation joined onto the table (the 214 and 321 shapes) still abstains. Statements with two or more base tables do not call the new count. A file Space with no ontology (#522) and held SQL confirmed with Yes (#524) do not call this gate. Not a word rule. Not PASS.

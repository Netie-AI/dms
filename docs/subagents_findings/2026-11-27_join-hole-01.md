# JOIN-HOLE-01

Keywords: JOIN-HOLE-01, unverified_join, CTE, self-join, sqlglot, _one_base_read, cte_over_join, dms#527

A CTE name is not an `exp.Table`. `_JoinRule.check` counted only those sources and returned when it saw one base table, so `WITH c AS (SELECT * FROM t) SELECT ... FROM c a JOIN c b` never reached the join checks. The parent served the fanned-out total (schools 24 against a true 10, enrollments 428 against a true 107).

The early return is now one read of one base table. The count walks the sqlglot AST: every FROM and JOIN item, in the main query, each CTE body and each subquery. A CTE name used twice, a second FROM item, a recursive CTE, or a set operation does not take the shortcut. It falls through to the same checks (`cte_over_join`, `derived_table_over_join`, `set_operation`, or the link rules). Statements with two or more base tables do not call the new count.

Named cost, each of these answered on the parent and now abstains: `cte_filtered_against_its_own_average`, `cte_divided_by_its_own_total`, `constant_union_branch`, `one_row_constant_cross_join`, `recursive_keyword_without_recursion`, `cte_scalar_count_reread`. A file Space with no ontology (#522) and held SQL confirmed with Yes (#524) do not call this gate. Not a word rule. Not PASS.

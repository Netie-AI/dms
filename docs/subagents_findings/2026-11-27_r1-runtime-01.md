## What

`DMS_RUNTIME_SELFCHECK` defaults off. Off, `GET /health` has no `runtime` key and `build_answer_envelope` returns the same fields it did before. On, `/health` adds `runtime.insights_timeout_s` (the effective timeout), `cortex_reachable`, `cortex_caller_kind` (`service`, `loopback`, or `unknown`), and `ov_reachable`. A loopback caller or a timeout under 30s also sets `runtime_degraded` and `banner_reason` on the health body and on every envelope. Text, SQL, badge, and route are not rewritten.

Loopback is the published demo viewer key, recognized by the existing sha256. A key with the service prefix is `service`. Anything else, including a missing key, is `unknown`. The key value is not returned and is not logged.

The process default for `DMS_INSIGHTS_TIMEOUT_S` stays 8s. Compose (api and api_dev) and `Start-DMSStack.ps1` pin 60 when the shell did not set one. Startup always logs the effective timeout. The degraded warning runs only when the flag is on.

Cortex `/health` and the box keepalive probe are not in this repo. R1-UI-COPY-01 renders the banner reason.

## Not a word rule

The new functions do not bind `question` or `prompt`. The caller class is a digest and a key prefix.

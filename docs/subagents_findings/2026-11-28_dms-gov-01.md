# DMS-GOV-01

Flag `DMS_GOV_CONSOLE` defaults off. Only the exact digit `1` turns it on.

Off, the gov router is not mounted. `guard_feature`, `guard_text`, and `guard_bytes` return before any scan or store read. Ask, ingest, and connect stay as they were.

On, a manager assignment sets daily and monthly token and USD caps and ask, create, and connectors. The deployment steward is a manager until a row says otherwise. An unassigned person is unlimited, so turning the flag on does not lock the install.

OpenVault has no per-user cap write. `GET /api/usage` returns tokens and model. `est_cost_usd` is absent on live events. `GET /api/keys/quota` is read-only. `PUT /api/ship/budget` is one install cap and is not called. A USD-only cap with unpriced events is `gov_usd_unpriced` (429). A token cap still uses `total_tokens`. Every limited provider key at its daily limit is `gov_key_cap`.

Question text is on the manager audit and dashboard only. A member gets 403 `gov_manager_required` and the body does not contain the question. Display redaction uses the same scanner and does not write a new finding.

Upload scan uses gitleaks rules vendored at `5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c` (196 compile, 26 skipped) plus `dms_core.pii.mask_payload`. The finding stores the type, the uploader, and the sha256. It does not store the secret. Binary files cannot be redacted, so redact is treated as block.

Governance is deterministic. The ask path is unchanged when the flag is off. Stub 52 was not remeasured. Not PASS.

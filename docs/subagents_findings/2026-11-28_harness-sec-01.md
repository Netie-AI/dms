# HARNESS-SEC-01

Flag `DMS_HARNESS_SEC` default off. Only the digit 1 turns it on. `true`, `yes`, and `on` stay off.

Off, ask, auth, feedback prompts, and SQL execution stay on the previous path.

On:

- Logs, SSE, errors, prompts, and generated apps redact planted secrets, provider-key shapes, and connection strings.
- `run_readonly` parses with sqlglot and refuses DDL, DML, multi-statement SQL, COPY, ATTACH, PRAGMA, and file readers before the cursor opens. Ungranted tables and, when a column map is passed, ungranted columns are refused the same way. The serving cursor stays read-only. A row cap and a wall-clock timeout apply. Postgres and MySQL sessions set a read-only transaction.
- Values, uploaded docs, and style prompts sit in XML data tags. Tool names must be on the allowlist. `skip_judge` on the model payload does not skip the judge.
- Generated apps are sanitised HTML plus a CSP. Docs and slides are redacted text.
- Provider calls check a per-tenant OpenVault budget and fail closed when it is missing. An audit row stores actor, prompt sha256, tables, and cost. `DMS_HARNESS_PII=1` masks sample cells the PII classifier flags.
- `dms-demo-` bearers fail closed on MCP lookup, the service bearer, and Insights unless `DMS_DEMO_KEYS` is 1.

Not a word rule. Stub 52 not remeasured. Not PASS.

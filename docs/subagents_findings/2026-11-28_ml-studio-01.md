# DMS-ML-01 modelling studio

Keywords: DMS_ML_STUDIO, forecast, classification, regression, clustering, held-out, leakage, OpenVault

## What is true

- Flag default off. Only the digit `1` mounts `POST /v1/studio/ml/runs` and `GET /v1/studio/ml/runs/{id}`.
- The route does not import the executor. `dms_api.wiring` loads `dms_executor.ml_studio` at call time. Import-linter stayed kept. `.importlinter` was not edited.
- SQL must be one read with an aggregate. The row cap is 8000. The provider sees column names and types, then metric JSON. Rows are not in that prompt.
- Tasks: forecast (seasonal naive, numpy Holt-Winters, detrended lag booster), classification (logistic, gradient boosting, random forest), regression (linear, gradient boosting, random forest), clustering (k-means versus random labels). The winner is chosen on the selection split. The card reports held-out metrics. `proven_solution` is true only when that winner beats the baseline on the holdout.
- `register_task("reinforcement", ...)` stores a note. `fit_frame` refuses it. See PARKING_LOT.md.
- No Alembic revision. Run records are JSON files.
- Dependencies added on the executor: `scikit-learn>=1.4,<1.8`, `pillow>=10,<12`. ETS is numpy, not statsmodels.

PREFLIGHT: PARTIAL. Deadline cuts, the serving lease, and conn-pool-01 were on file. Nothing covered the 60s leg against the 24.55s ask deadline, the uncached sqlglot re-parse, or exact COUNT(DISTINCT) on every text column.

`DMS_SCALE_BUDGET` defaults off. Only the digit 1 turns it on. On, `model_leg_budget_s` is the time left on the ask deadline (the ask-back reserve still applies when that flag is also on, and the leg gets the smaller one). The in-flight client is closed and `/v1/insights/cancel` is posted. `CortexClient.complete` returns before the HTTP call when that time is already spent, and otherwise uses the time left instead of a fixed 2s. Off, the leg timeout and the suggestion call are unchanged.

The serving dialect is loaded from `Executor.startup` and on the first parse. Parses are cached by `(sql, dialect)`. `live_ask` keeps one slot so later gates copy the first tree. `validated_sql_reason` passes that tree into the currency check and the join rule.

Serving reads keep one read-only parent. Idle cursors are capped. A broken cursor is not reused. A writer closes the idle parent before opening the file read-write. An external `duckdb.connect` on that file does the same when no serving cursor is out, because DuckDB will not open the file read-write beside the locked parent. `close_lakes` still drops it, and the test suite does that after each test. The parent sets `memory_limit` from `DMS_LAKE_MEMORY_LIMIT` (default `1GB`) and `threads` from `DMS_LAKE_THREADS` (default 4, ceiling 32) before the config lock.

A text column's index count is `approx_count_distinct`. Above twice `INDEX_COLUMN_CAP` the column is capped and not read. At or under that line, an exact `SELECT DISTINCT ... LIMIT 501` is the cap decision, so a small column still stores its full set and a column just over the cap stores nothing.

`scripts/verify/scale_smoke.py` builds a scratch file, marks it seeded, and reports p50/p95 at concurrency 1, 5, and 20. CI passes `--rows 2000`. The demo warehouse file is not opened. A local run at 2000 rows, one parent open: concurrency 1 p50 2.4ms p95 6.5ms, concurrency 5 p50 6.8ms p95 8.8ms, concurrency 20 p50 21.2ms p95 30.4ms. Cortex's COUNT wrapper and the semantic-layer reread are out of scope.
